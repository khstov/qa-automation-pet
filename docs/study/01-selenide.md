## Что такое Selenide

Selenide — библиотека для UI-автоматизации на Java поверх Selenium WebDriver.
Она предоставляет короткий API для поиска элементов, действий и проверок, а
также сама ожидает выполнения проверяемого условия в пределах таймаута.

Базовая схема теста:

```java
open("/text-box");
$("#userName").setValue("Iaroslav QA");
$("#submit").click();
$("#output").shouldBe(visible);
```

1. `open` открывает страницу.
2. `$` находит один элемент по CSS-селектору.
3. `setValue` и `click` выполняют действия.
4. `shouldBe` и `shouldHave` проверяют состояние элемента.

## Элементы и локаторы

`SelenideElement` хранит описание элемента:

```java
private final SelenideElement emailInput = $("#userEmail");
```

В текущем Page Object используются ID: `#userName`, `#userEmail`, `#submit`.
Это короткие и понятные локаторы. В рамках темы flaky-тестов отдельно разберём,
почему стабильный ID лучше длинного XPath или селектора, зависящего от позиции
элемента.

## Действия

В текущем проекте используются:

- `setValue(value)` — очистить поле и ввести значение;
- `scrollTo()` — прокрутить страницу к элементу;
- `click()` — нажать на элемент;
- `open(path)` — открыть страницу относительно `Configuration.baseUrl`.

## Проверки и ожидания

Основные проверки текущего теста:

```java
output.shouldBe(visible);
outputName.shouldHave(text(fullName));
output.shouldBe(hidden);
```

`shouldBe` проверяет состояние, например `visible` или `hidden`.
`shouldHave` проверяет свойство, например текст. Selenide повторяет проверку до
успеха или истечения таймаута. Поэтому фиксированный `Thread.sleep` здесь не
нужен.

В практическом задании после `open("/text-box")` нужно добавить ожидание
видимости поля имени. Тогда метод `openPage()` будет возвращать управление
тесту только после того, как основной элемент страницы готов к работе.

## Конфигурация в проекте

В `BaseUiTest` заданы:

```java
Configuration.baseUrl = "https://demoqa.com";
Configuration.browserSize = "1920x1080";
```

Поэтому Page Object открывает относительный путь `/text-box`. После каждого
теста браузер закрывается через `closeWebDriver()`, и следующий тест получает
новую браузерную сессию.

## Page Object в текущем проекте

`TextBoxTest` содержит сценарий и тестовые данные. `TextBoxPage` содержит
локаторы, действия со страницей и проверки результата. Тест читается как
последовательность пользовательских действий, а CSS-селекторы не попадают в
тестовый метод.

Файлы для разбора:

- `src/test/java/ui/TextBoxTest.java`;
- `src/test/java/ui/pages/TextBoxPage.java`;
- `src/test/java/ui/BaseUiTest.java`.

## Что нужно уметь объяснить

1. Selenide работает поверх Selenium WebDriver.
2. `$` возвращает один `SelenideElement`.
3. Действия выполняются методами элемента: `setValue`, `click`, `scrollTo`.
4. `shouldBe` и `shouldHave` являются проверками с ожиданием.
5. Фиксированный `sleep` не нужен, когда можно ожидать наблюдаемое состояние.
6. `Configuration.baseUrl` позволяет открывать относительные пути.
7. Локаторы и действия вынесены из теста в Page Object.

## Практика

1. Найти в `TextBoxPage` метод `openPage()`.
2. После `open("/text-box")` добавить
   `fullNameInput.shouldBe(visible);`.
3. Запустить `./gradlew test --tests ui.TextBoxTest`.
4. Найти в `TextBoxPage` локатор поля email.
5. Найти проверку успешной отправки формы.
6. Найти проверку отклонения некорректного email.
7. Объяснить, почему тесты не используют `Thread.sleep`.

## Практика 2 — Radio Button

Следующий согласованный сценарий: выбрать `Yes` на странице
`https://demoqa.com/radio-button` и проверить показанный результат.

На странице используются:

- `#yesRadio` — radio input `Yes`;
- `label[for='yesRadio']` — видимая кликабельная подпись `Yes`;
- `.text-success` — выбранное значение в результате.

Задача:

1. Создать `ui.pages.RadioButtonPage`.
2. Описать элементы для клика по `Yes` и проверки результата.
3. Создать `openPage()`, который открывает `/radio-button` и ожидает видимость
   подписи `Yes`.
4. Создать действие выбора `Yes`.
5. Создать проверку, что результат содержит `Yes`.
6. Создать `ui.RadioButtonTest`, наследующий `BaseUiTest`.
7. Запустить только `ui.RadioButtonTest`.

Сначала пользователь самостоятельно пишет `RadioButtonPage` и присылает код на
проверку. После проверки Page Object создаётся тест.
